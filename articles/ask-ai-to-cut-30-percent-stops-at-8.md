自サイトの案内文 14 本（1,149〜1,797 字）を `claude -p --model claude-opus-5` に「20〜30% 短くしてください」と頼み、指示を 4 段（制約なし／構造固定／＋数字と条件文を残せ／＋箇条書き可）に分けて 56 本を生成しました。字数の変化率、「数字＋単位」の残存、境界文（条件・限界・例外を述べた文）の残存を別々に数えています。

## 先に結論

1. **−20% に届いたのは 56 本中 3 本。** 中央値は 0（制約なし）−6.5%／A（構造固定）−6.9%／B（＋数字と条件文を残せ）−8.2%／C（B＋箇条書き可）−8.4%。
2. 条件の差（≤1.3 pt）は、同じ入力を 3 回投げて測った再現の幅（中央値 6.6 pt）の**内**。「残せ」が圧縮を下げるかは**識別できない**（HOLD）。
3. 制約を全部外した条件 0 でも 0/14。**「残せ」だけでも「構造を変えるな」の明示指示だけでも、届かない理由を説明できなかった**（何が天井かは特定していない）。
4. 届かないのに「数字＋単位」の表記は消える（27/56 本・ほぼ個数「3 つ」「5 つ」）。金額は 18/18 残った。境界文 116 のうち落ちたのは 4＝**同じ 1 文が 4 条件すべてで**削られた（「合否条件を通した検証の結果」→「検証の結果」）。

## 設計（生成の前に凍結したもの）

- 材料: 自サイト `/works/guide/` の 14 本。frontmatter・HTML タグ・末尾 CTA・空白を除いた字数で 1,149〜1,797 字。sha256 を凍結。
- 数字＋単位（atom・154 個）と境界文（29 文）を先に抜き出して凍結。
- 指示（逐語）:
  - **0**: 次の本文を 20〜30% 短くしてください。短くした本文だけを出力してください（前置きや説明は不要）。
  - **A**: 0 ＋「見出し・段落・箇条書きの構造は変えないでください。」
  - **B**: A ＋「数字と、条件・限界・例外を述べた文は残してください。」
  - **C**: B ＋「ただし列挙は箇条書きに変えて構いません。」
- 仮説: H1 B は A より圧縮率が下がる／H2 A は −20% に届くが数字か境界文が落ちる本が半数以上／H3 C は B より縮む。
- HOLD の閾値: 予備（3 本 × A × 3 回）の再現の幅の中央値＝**6.6 pt**（同じ入力が −21% と −7% に割れた記事もあった）。条件間の差がこれ未満なら「識別できない」。
- 本番は記事ごとに条件の順をランダム化（乱数種 20260919）。各 1 回。条件 0 は A〜C の 42 本を集計した後、外部の精査「A〜C は全部構造固定を含む＝届かない理由を分離できていない」を受けて足しました。

生成は `claude -p` に本文を stdin で渡しています（CLAUDE.md の無い一時フォルダ）。`-p` でも Claude Code の system prompt は載るので、素のチャット API と同条件ではありません。

## 数える器

- 字数: 空白を除いた文字数の変化率。
- atom: `[\d,]+(?:\.\d+)?\s*(円|件|本|日|%|項目|つ|…)` の multiset。原文より出現回数が減ったら「表記が消えた」。**意味の裁定はしない**（「3 つの確認」が箇条書き 3 項目になっても「消えた」に数える）。
- 境界文: 記号と空白を落として正規化した文字列の包含で自動一致。一致しないものは、出力側でいちばん近い文（`difflib`）を添えて人が「言い換えて残った／落ちた／反転」を裁定。
- 構造: 見出し数・箇条書き数。

```python
ATOM = re.compile(r'([\d,]+(?:\.\d+)?)\s*(円|件|本|日|時間|営業日|%|％|項目|段階|か所|回|人|社|通|枚|行|字|ミリ秒|秒|分|か月|つ|層|型|種|点|倍)')
def atoms_of(s):
    d = {}
    for m in ATOM.finditer(plain(s)): k = f'{m.group(1)} {m.group(2)}'; d[k] = d.get(k, 0) + 1
    return d
lost = {k: c - a1.get(k, 0) for k, c in a0.items() if a1.get(k, 0) < c}
```

## 仮説の裁定

- H1（B は A より縮まない）→ **HOLD**（差 1.3 pt < 6.6・向きは逆）。
- H2（A は −20% に届くが落ちる）→ **前段で外れ**（到達 0/14・条件 0 でも 0/14）。後段だけは起きた（表記か境界文が落ちた本 9/14）。
- H3（C は B より縮む）→ **HOLD**（差 0.2 pt）。

## うまくいかなかったこと

- 予備の初回は本文を argv で渡して届かず、9 本とも「本文が含まれていない」の応答が返った。stdin に変えて再走（失敗分も残しています）。
- 設計時に書いた材料の字数（1,563〜2,319）は推定値で、凍結した材料の実測は 1,149〜1,797 字だった。
- 「残せ条件が天井」という題で始めたが、条件を外しても届かず、題を引き直した。

## 言えないこと

他のモデル・他の温度。「−25% ちょうどに」と 1 点で頼んだ場合。材料が 3,000 字超の場合。2 回目以降の再現（各 1 回）。文章の良し悪し。

## 持ち帰り: 短縮を頼むときの受入条件（3 行）

| 列 | 書き方 |
|---|---|
| 短縮率 | 字数（空白除く）の変化率が −X% 以下 |
| protected atom | 原文の「数字＋単位」の出現回数が出力で減っていない（表記の有無だけ・意味は見ない） |
| boundary claim | 条件・限界・例外の文が言い換えでも残っている |

「短くして」は字数の代理指標で、確かめたいのは「数字と条件が残ったか」。両方を別の列で数えると、届いていないことと、届かないまま落ちていることが同時に見えます。
