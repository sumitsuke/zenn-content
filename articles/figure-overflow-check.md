記事用の図 8 枚を Pillow（PIL）で生成して、目で見て直して「もう大丈夫」と思ってから、生成器に「はみ出し検査」を足して数えたら、**3 件残っていました**。目視で取れる欠陥と機械で取れる欠陥は別物だった、という短い記録です。人 vs 機械ではなく、人＋機械の話。

## 時系列

1. 8 枚を生成 → 目視で c1・c2 の**フッターと最下段の切れ**を見つけて直す
2. 「もう大丈夫」と判断して見せる → 指摘「所どころ文字が枠からはみ出ている」
3. 生成器に **レイアウト検査 4 種**（はみ出し 3 種＋重なり 1 種）を足す（描いた文字を全部記録して数える）
4. **さらに 3 件**（画面外 2・枠外 1）が出る → 直す → 0

## レイアウト検査 4 種（生成器に埋め込んだ・簡易）

`ImageDraw.text` を包んで、描いた文字の左上・右端・行の高さを全部記録し、`rect()` で描いた枠も記録します。書き出す前に数えるのは 4 つ:

| 検査 | 条件 | 今回捕まえた |
|---|---|---|
| 画面外 | 文字の右端 > 画像幅 − 40 | 2 件（右列のラベルと赤い注記・1580／1590 px） |
| 枠外（右） | 文字の左端を含む最小の枠の右端 − 12 を越える | 1 件（39〜44 px 越え） |
| 枠外（下） | 文字の下端が枠の下端 − 4 を越える | 0 |
| 文字の重なり | 同じ行帯で x 範囲が重なる | 0 |

```python
_TEXTS, _RECTS = [], []
_orig = ImageDraw.ImageDraw.text
def _logged(self, xy, text, fill=None, font=None, *a, **k):
    _orig(self, xy, text, fill=fill, font=font, *a, **k)
    for i, ln in enumerate(str(text).split(chr(10))):
        _TEXTS.append((xy[0], xy[1] + i * font.size * 1.2, xy[0] + font.getlength(ln), ln, font.size))
ImageDraw.ImageDraw.text = _logged
# rect() で _RECTS に (x0, y0, x1, y1) を積み、save() の直前に 4 種を数えて 🔴 で印字。0 になるまで書き出さない
```

## 検査が見ていないもの（ここが本題）

レイアウト検査 4 種が 0 でも、**フォントに無い字（≥・β・✓・絵文字）が空白で描かれる欠落**は、この検査では見えません。字集合との照合という**別系統**の検査です。目視で見つけたのはこちらでした。

逆に、目視で見逃した 3 件は数 px の越えで、縮小表示ではほぼ見えません。**目視＝全体の違和感と欠落／bbox 検査＝今回の描画条件で数 px の越えを機械的に拾う**（`getlength` と行高の近似で、実際の描画 bbox そのものではない。厳密にするなら同じ描画条件で `textbbox()` を使う）。見るものが違うので、どちらかで代替できません。

もう 1 つ。折り返し関数が「（」の直後で折れない規則になっていて、`（bold-chars.txt）` のような長い英字が枠を越えていました。検査は「越えた」を数えるだけで、原因（折り返し規則）は教えません。原因は現物を見て直す。

## 手順として

1. 生成器に「描いた文字を全部記録する」フックを 1 本入れる
2. 書き出す前に画面外・枠外（右／下）・重なりを数える。0 になるまで書き出さない
3. **検査が見ている範囲を名乗らせる**（レイアウト 4 種／glyph 欠落は別）
4. 目視は残す。見るのは全体の違和感と欠落で、数 px は機械に任せる
5. 折り返し規則とフォントの字集合は、生成の前に毒（長い英字・無い字）で確かめる

検査器は人の目を置き換えるものではなく、**人が苦手なところ（数 px・8 枚全部）だけを機械に渡す**ためのもの。
